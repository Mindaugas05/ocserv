# ocserv-lab

A Dockerized [ocserv](https://ocserv.gitlab.io/www/manual.html) (OpenConnect VPN server) lab for connecting a client router, with support for both password-based and certificate-based authentication.

## Quick Start

### 1. Clone and navigate

```bash
git clone <github-url>
cd ~/ocserv-lab
```

### 2. Generate certificates

```bash
chmod +x scripts/generate-certs.sh
./scripts/generate-certs.sh
```

### 3. Build and start the container

```bash
sudo docker compose build
sudo docker compose up -d
```

### 4. Upload the CA certificate to your client router

Upload `ca_cert.pem` to your client router so it can trust the server.

## Authentication Configuration

Choose **one** of the following options.

### Option A: Password-based authentication

Create a password for a user (example username: `router-password`):

```bash
docker compose exec ocserv \
    ocpasswd \
    -c /etc/ocserv/passwd/ocpasswd \
    <username>
```

You will be prompted to enter and confirm the password:

```
Enter password:
Re-enter password:
```

The password database is persisted on the host at:

```
~/ocserv-lab/passwd/ocpasswd
```

To verify the entry was created:

```bash
cat passwd/ocpasswd
```

### Option B: Certificate-based authentication

Make sure the client certificate and key were generated by `scripts/generate-certs.sh`:

- `router-client-cert.pem`
- `router-client-key.pem`

Upload both files to your client router.

## Logs

```bash
sudo docker compose logs --tail=50 ocserv
```

## Troubleshooting

### DTLS issues

If you run ocserv behind a reverse proxy or across multiple hosts, DTLS may not work as expected. See the OpenConnect documentation:

- [DTLS and reverse proxies](https://docs.openconnect-vpn.net/recipes/ocserv-multihost/#dtls-and-reverse-proxies)
